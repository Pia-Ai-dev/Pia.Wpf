# Plan — Callouts (`:::tip` / `:::warn` / `:::info` / `:::success`)

**Goal:** when Pia emits Markdown like

```
:::warn Datenverlust
Dieser Schritt löscht alle Reminders aus dem Profil.
:::
```

the renderer surfaces a `PiaCallout` block in place of that source range
instead of falling back to raw paragraph text.

**Surface (already built):**
- `Pia.Controls.Chat.PiaCallout` with `Kind` (`Info` | `Tip` | `Warn` |
  `Success`), `Title`, `Body` DPs. Resolves accent + soft + icon from
  Pia tokens.

**Why:** semantic emphasis. Lets the model emit warnings before
destructive actions, tips for setup, info notes that are visually
distinct from prose without abusing blockquotes.

---

## How it'll work end-to-end

1. Markdig parses `:::kind …` blocks via a custom `BlockParser` and
   produces a `CalloutBlock` AST node (a `ContainerBlock` subclass).
2. `PiaMarkdownRenderer` recognizes `CalloutBlock` and emits a
   `BlockUIContainer` hosting a `PiaCallout`.
3. The body inside the fence is **also** Markdown — render it recursively
   into a `FlowDocument` slice and hand that to `PiaCallout.Body`. (For
   v1, treat body as plain text; v2 supports inline formatting.)
4. Pia's system prompt is updated to teach the model the syntax.

---

## Step 1 — Parser

Create `src/Pia.Wpf/Controls/Markdown/Callouts/`:

- `CalloutBlock.cs` — `public sealed class CalloutBlock : ContainerBlock`
  with a `Kind` property (`tip`/`warn`/`info`/`success`) and optional
  `Title`.
- `CalloutBlockParser.cs` — derives from `Markdig.Parsers.BlockParser`.
  Recognizes a line starting with `:::` followed by a kind keyword and
  optional title. Closes when a line of exactly `:::` is seen. Pattern is
  similar to Markdig's `FencedBlockParserBase<CodeBlock>`; mirror its
  shape.
- `CalloutExtension.cs` — `IMarkdownExtension` that calls
  `pipeline.BlockParsers.AddIfNotAlready<CalloutBlockParser>()`.

Wire it into `PiaMarkdownRenderer`:

```csharp
private static readonly MarkdownPipeline _pipeline = new MarkdownPipelineBuilder()
    .UseAdvancedExtensions()
    .Use<CalloutExtension>()
    .Build();
```

## Step 2 — Renderer

In `PiaMarkdownRenderer.RenderBlock`, add a case:

```csharp
case CalloutBlock callout:
    return RenderCallout(callout);
```

`RenderCallout` builds a `PiaCallout`, sets `Kind` from the parsed
string, sets `Title`, and for v1 sets `Body` to the joined inner text.
Wrap the control in a `BlockUIContainer` with margins matching code
blocks.

For v2 (later): the `Body` DP type is currently `string` — change it to
`object` so we can pass a `FlowDocument` slice rendered from the inner
blocks. Update `PiaCallout.xaml` to host that slice in a `RichTextBox`
instead of a `TextBlock`.

## Step 3 — Prompt tuning

Locate the Pia system prompt (likely a template under `Services/` or a
resource file — find by grepping for a German marker like "Du bist Pia").
Append a paragraph describing the syntax with one example per kind.
Limit to one callout per turn unless really needed (avoids visual noise).

## Step 4 — Smoke test render path without the model

Add a debug-only seeded payload in `AssistantViewModel` (e.g. `[Conditional("DEBUG")]`
method or hidden `/calloutdemo` command) that injects a fake assistant
message containing all four kinds. Useful for screenshotting and during
development before prompt-tuning lands.

---

## Acceptance

- Type `/calloutdemo` (or whatever debug trigger you wire) — four
  callouts render with correct accent stripes + icons in both light and
  dark mode.
- Send a real prompt that asks Pia to "warn me about deleting all
  reminders before doing it" — the answer renders a warn callout above
  or in line with the action card.
- A malformed fence (`:::warn` with no closing `:::`) does **not** crash
  the renderer — it falls back to plain paragraphs.

## Risks / notes

- Markdig's API for custom block parsers is fiddly; budget half the day
  on Step 1 alone. Reference: `Markdig.Extensions.CustomContainers` —
  there is already a `CustomContainerExtension` (`:::name` syntax). You
  can probably skip writing a parser from scratch and just consume
  `CustomContainer` AST nodes, switching on `node.Info` for the kind.
- The `Body` content is user-facing text generated by the LLM. Don't
  log it at Information level (use `SensitiveDebug`).
- Don't double-render: when a callout is in flight, the source range
  must NOT also produce a fallback paragraph. Verify the parser claims
  its lines via `BlockState.BreakDiscard`.
