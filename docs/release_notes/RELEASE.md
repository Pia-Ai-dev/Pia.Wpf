# Pia next

## Transcription and consent

- The notice before a transcription now names what Pia does with the
  transcript: transcription on this device; if you choose, saving it as a
  file or in the vault, where your AI provider works it into your knowledge
  base; and, if you choose, a summary by your AI provider.
- Transcripts you save as a file or in the vault carry the consent record:
  who consented under which notice and when, and any revocation.
- Pia keeps its own copy of that record only while a vault note or chat
  from the session exists, instead of for 14 days; if you keep nothing in
  Pia, it goes when the session ends.
- Revoking a speaker's consent lists the session's copies: vault notes and
  chats can be deleted right there, exported files are shown for you to
  remove.
- Speaker numbers stay unique when a transcription is restarted, so
  renaming or revoking a speaker always affects exactly one person.

## Teams meetings

- The host's confirmation before a scheduled or joined meeting now names
  what happens to the transcript, and it is kept with the saved note
  together with the notice the host confirmed.

## AI feedback

- "Report this answer" has a "This concerns data protection" box. With Pia
  Server 1.4, when a report was only stored and nobody was notified, Pia
  says so.
- Concerns about Pia's AI behaviour go to ki@pia-ai.de.

## Encryption

- With Pia Server 1.4, a device set up with the recovery code has to prove
  it holds your account's key. Pia sends the server what it needs for this
  on its own.
- A device the server lists as waiting for approval now asks to be set up
  again instead of syncing on.
- Setting up Pia on another computer for an account that is already
  encrypted now leads straight to the recovery code or an approval.
